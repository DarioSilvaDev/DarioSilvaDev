## 🏗️ Mi forma de diseñar sistemas

> **Primero entiendo el problema. Después diseño la solución.**

Prefiero una arquitectura pragmática antes que introducir complejidad innecesaria.

Cuando diseño un backend, intento seguir un proceso similar a:

**Requerimientos de negocio → Modelo de dominio → Modelo de datos → Diseño de API → Arquitectura → Implementación → Testing**

Algunas de las preguntas que considero importantes antes de introducir una nueva tecnología o patrón:

* ¿Qué problema estamos intentando resolver?
* ¿La complejidad agregada está justificada?
* ¿Qué trade-offs estamos aceptando?
* ¿Cómo evolucionará esta decisión si el sistema crece?
* ¿Cómo vamos a probarla?
* ¿Qué impacto tendrá en la operación y mantenimiento del sistema?

Creo que una buena ingeniería backend no consiste en utilizar la mayor cantidad posible de tecnologías, sino en tomar **buenas decisiones técnicas para el problema que tenemos delante**.
